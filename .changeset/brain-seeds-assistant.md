Sections whose default lives in code, kept in step with the code. Every version now records who wrote it: `assistant_section_versions.created_by_kind`, `"person"` or `"code"` (a schema change: one column, defaulting to `"person"`, so nothing existing is ever overwritten on a guess; `sql/upgrade-0.10-to-0.11.sql`, safe twice, with an optional `assistant.code_actors` setting that marks versions your own code signed as the code's). A section's first text is its v1 (`createSection` and `seedDefaultSections` both record it), so "roll back" can always reach the seed. `ensureSection(db, tenantId, seed, { signer })` creates a missing section from the seed, does nothing when the brain holds the seed's text, adopts the seed as the next version over text the code wrote (including a pre-0.11 seed with no versions), and keeps a person's edit (`outcome: "edited"`, `differsFromCode: true`); the seed's budget, required phrases and description follow it, and two servers adopting at once make one publish. `resetSectionToCode` puts the code's text back, signed as the code's, so the section follows the code again; `listSectionsForEditor(db, tenantId, { seeds })` adds `headKind`, `codeDefault` and `differsFromCode` per row. A bare-string actor still means a person; code passes `fromCode("seed")`. `publishSection` now refuses a `baseVersion` past the head as `base_ahead` instead of `conflict` (nothing newer was published; the editor's copy came from elsewhere), so an exhaustive switch over `PublishResult.reason` gains a case. The fresh-install DDL is now `sql/assistant-0.11.0.sql` (was `assistant-0.9.0.sql`).
