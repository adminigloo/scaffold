Product lines on one subscription, and one customer per tenant (stripe 0.6). `previewPlanChange` / `changePlan` take an `itemId` and swap only that line's item (metadata stamped on the item; without one, the one-item rule holds as before). `previewAddLine` / `addLine` add a line as an item of the existing subscription — prorated and charged now, `pending_if_incomplete`, the proration date bound as for a change, and `addLineIdempotencyKey(subscription, line, { previousItemIds })` so two tabs adding from the same state add one item, while adding a line back after dropping it is always a new request (the key carries the latest invoice and the line's earlier items). `addLine` reads the subscription again after the update and answers that read — a new item missing from it is refused (`not_added`), never reported as added from a replayed answer. `removeLine` takes one line's item off with its unused time invoiced at once as a credit on the customer's balance (`always_invoice`, so it isn't stranded if the last line is cancelled later) and refuses the last item (that's a cancellation at the period's end). `resolveStripeCustomer({ tenantId, userId, knownCustomerId, email, create })` finds the tenant's one customer — its own, or the one carrying `metadata.tenantId`; with `userId` (pass it only for that person's own personal workspace) a person's customer from the shop that belongs to no tenant yet is adopted — and makes one only when asked; `prepareCompanyCheckout` uses it, counts only plan subscriptions (`isPlanSubscriptionFor`: not the shop's, not another tenant's) and reports `hadSubscription` (one free trial per customer). `subscriptionSnapshot` lists every item (`items`, `itemsComplete`, and each Price's own `priceMetadata`).
